A brief word on space syntax

- associated with the work of Hillier & Hanson at the Bartlett School of Architecture

- an elaboration of network analysis, but for built space

- architects have found that certain measures hold implications for how a building might affect/promote/change social relationships within the space

- archaeologists say, 'if that's the case for buildings now, then that's likely for buildings in the past; therefore we might argue it is a method that lets us understand built space even in the absence of other archaeological data'

  • spaces can be represented as graphs based on principles of intervisibility
  • isovist - what can be seen from any particular point
  • axial space - straight line visibility
  • integration - uses a version of 'shortest path', the number of steps from the street to all other street segments (or rooms in a building). Illustration shows integration map for Brasilia.
  • integration is a bit like figuring out 'closeness' in a social network.
  • choice is a bit like measureing flow betweeness - take a value, choose a starting point, and divide that value as you move to adjoining steps. When you're out of value, you've gone as far as you can; what parts are connected up?
  • depth - pick a point, measure steps to all other points. Repeat for all points. Streets/room with lowest overall values shows you their 'depth' within the graph

Supervised vs. Unsupervised

Supervised: here are 1000 examples from class 1, here are 1000 examples from class 2, apply this set of rules (ie, an algorithm) to decide which category a new unlabeled example belongs to.

- A really good explainer for one such algorithm https://mlu-explain.github.io/decision-tree/

- classification - dealing with categories (ie: dressel-24)

- regression - dealing with values (ie, no labels: weight) (see https://mlu-explain.github.io/ for a variety of algorithm explainers)

 

Unsupervised: deploys various algorithms to find clusters of 'similar' data points, but susceptible to noise; messy data (like in archaeology) usually screws everything up.

function ELIZA GENERATOR(user sentence) returns response
   Let w be the word in sentence that has the highest keyword rank
   if w exists
       Let r be the highest ranked rule for w that matches sentence
       response ← Apply the transform in r to sentence
       if w = 'my'
           future ← Apply a transformation from the ‘memory’ rule list to sentence
           Push future onto the memory queue
       else (no keyword applies)
           Either
               response ← Apply the transform for the NONE keyword to sentence
           Or
               response ← Pop the oldest response from the memory queue
   Return response
